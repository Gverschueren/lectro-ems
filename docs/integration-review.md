# EMS vendor API review

Reviewed 23 October 2026. This is a technical integration screen, not a legal opinion. No vendor credentials have been issued or stored. A connector stays disabled until the integration route, customer consent, API terms, rate limits, and any charges are confirmed for Lectro's intended B2B service.

| Provider | Official interface and auth | Monitoring / control | Commercial position and next step |
| --- | --- | --- | --- |
| Shelly | Cloud Control API. Customer needs a Shelly Cloud account and paired devices. The owner creates an authorization key and supplies the correct tenant server URI. Current published limit: one request per second. Local Gen1 HTTP API / newer RPC is an alternative through the gateway. | Cloud API documents status reads and control/settings writes. Keep the EMS connector read-only in phase one. | Public docs say registered users can use the Cloud API but do not spell out Lectro's multi-customer/commercial redistribution rights or SLA. Ask Shelly for written terms and an OAuth/delegated-consent option. Do not ask customers to paste a key until rights and secure credential handling are ready. |
| HomeWizard | No public cloud-to-cloud integration API found in the official API guide. Local API: v1 over HTTP; v2 over HTTPS with a device-issued Bearer token. v2 token setup requires a physical button press. The API must be enabled and the gateway must be on the same LAN. | P1 and kWh meter measurements are available. Plug-In Battery uses v2. The P1/kWh-meter `/api/batteries` resource may expose battery-controller state and modes; no battery write path is implemented here. | The guide describes personal automation/home-automation/graphing use. It does not grant an explicit commercial multi-customer service license. Ask HomeWizard before using this in a paid/customer service. **Prototype connector:** read-only P1 v1 normalization via the virtual gateway. |
| SMA | Official SMA Developer Portal APIs use OAuth 2.0. Developer credentials, an application/user-consent flow, and contract/provisioning are required for production. The portal offers sandbox systems and rate limits. | Monitoring API: plant/device/history data. GridControl API can remotely steer supported systems. Live API is intended for near-time UI views and explicitly not for constant monitoring. | B2B plans are usage-priced. The current API plans publish fees per monitored system/size and a separate priced live-call quota. Cost can materially affect an EMS portfolio; model it before offering SMA integration. |
| Huawei FusionSolar | Official Northbound/open APIs are available through FusionSolar. A third-party OAuth 2.0 client must be applied for; Huawei's Europe instructions direct applicants to `huaweipartners@huawei.com`. API access is separate from an ordinary third-party portal login. | Plant list and system/measurement queries are documented. Scope depends on the granted northbound API and plant permissions. Use monitoring first; no write API in this prototype. | Partner/application approval and applicable Huawei agreement required. The publicly readable docs do not establish an unrestricted commercial license; obtain approval, endpoint/rate limits and data-retention terms before production. |
| SolarEdge | Official SolarEdge Developer Platform API V2: OAuth 2.0. Create a developer account/application and authorize the owner's or customer-granted fleet. | Current docs advertise live and historical site data, power, inventory, and equipment telemetry. The public V2 surface is described for third-party/partner integrations and energy-management apps. | Public entry page says “free to start”, but detailed rate limits, production quotas and commercial terms are in the developer docs/account. Review those before forecasted polling. Strong candidate for the first cloud-to-cloud connector after app registration and terms review. |
| Marstek Venus | Official Marstek Device Open API Rev 3.1 is local LAN API, enabled by the owner in the Marstek app; JSON request/response over UDP. It is not the same as a public cloud API. | Query and configuration/control methods exist. Supported methods vary by model/firmware, and enabling local API may disable some built-in device functions to prevent conflicts. | The official specification says “as is” and “local use only,” places lawful use responsibility on the user, and gives no commercial SaaS license or SLA. Confirm the exact Venus model/firmware and written commercial permission. Do not use community mappings as the sole production basis. |
| Anker SOLIX | Anker Open Platform advertises an API and SDK for integrating Anker devices into apps. SOLIX API documentation is behind platform login; access model, OAuth/delegated consent, scopes, quotas and technical details are not publicly verifiable from the portal. | Product and action coverage varies. Anker's official support says there is no public API for its Smart Plug; that does not establish access for every SOLIX product. | Apply through the official Anker developer/partner platform and obtain written B2B access/terms. Do not scrape mobile-app or private cloud endpoints as the sole connector. |
| Charging stations | Prefer OCPP from the charge point to the EMS/CSMS over the public Internet. OCPP 1.6 remains common; OCPP 2.0.1 has improved security and smart charging; OCPP 2.1 is the current OCA release and adds DER/bidirectional features. Manufacturer-specific cloud REST APIs remain adapters where no usable OCPP is available. | Monitoring depends on the charger and OCPP version/profile; OCPP smart charging supports charging limits/schedules. The EMS will keep writes off until per-site permission and limits are approved. | OCPP is an open protocol, not a guarantee every charger exposes every function or that a vendor cloud API is commercially available. Confirm model, firmware, OCPP profile, CSMS configuration, and owner's authorization. OCA conformity certification is separate. |
| Other inverters, batteries, meters | First check the manufacturer's official cloud/API and written API terms. Where cloud access is absent, prefer documented Modbus TCP/RTU or SunSpec over a gateway on the customer LAN. | Telemetry and control registers are model/firmware-specific; only expose read-only points until a signed command map and safe limits are approved. | No generic promise of commercial rights follows from a local protocol being documented. Keep one adapter per manufacturer/protocol with explicit model/version capability declarations. |

## Engineering decisions from this review

1. Treat cloud-to-cloud as the default where the manufacturer offers a documented, supportable partner API. Use the gateway only for local protocols, discovery, buffering, and devices without a suitable cloud API.
2. Do not implement cloud login scraping or reverse-engineered private APIs as the only commercial path.
3. Store OAuth refresh tokens and API credentials server-side, encrypted with a rotatable key. Keep per-installation grants and revoke them when a customer disconnects a plant.
4. Rate-limit by vendor credential and installation. Respect SMA's live API restriction, Shelly's published one-request-per-second ceiling, and each provider's current quotas.
5. Separate telemetry permission from control permission. The initial EMS exposes no control command endpoint.
